# 哈吉米推什么推

中国海洋大学《移动软件开发》实验 4 的差异化推箱子实现。

## 设计定位

- 黑猫哈吉米作为真实照片角色。
- 深黑蓝页面外壳 + 猫眼绿强调 + 米白棋盘。
- 游戏世界中的罐罐、猫碗和纸箱采用扁平插画，与真实黑猫形成反差。
- 四个实验关卡保留课程文档中的 8×8 地图结构。
- 文案采用轻量玩梗风格，不影响基础操作的可理解性。

## 页面

- `pages/index`：首页、关卡列表、进度、本地最佳成绩。
- `pages/game`：Canvas 游戏页、方向键、滑动、撤回、重开、步数/推动统计、通关弹层。
- `pages/solutions`：通关后解锁每关理论最少步数及标准路线。

## 关卡

1. 哈吉米，启动！
2. 猫猫祟祟
3. 不是，猫们？
4. 有点脏了

四关地图沿用课程实验提供的原始地图编码：

- `0`：地图外
- `1`：墙
- `2`：道路
- `3`：终点
- `4`：可推动物
- `5`：玩家

视觉上重新映射为：

- 玩家 → 哈吉米
- 箱子 → 猫罐罐
- 终点 → 猫饭碗
- 墙 → 封好的快递纸箱

## 最优解

按“玩家每移动一格记 1 步”定义理论最优解，并使用 BFS 离线求解后写入 `data/levels.js`。

| 关卡 | 理论最少步数 | 该路线推动次数 |
|---|---:|---:|
| 1 | 51 | 11 |
| 2 | 10 | 6 |
| 3 | 51 | 14 |
| 4 | 61 | 20 |

项目内已经再次逐步执行四条路线，确认全部可以合法完成对应关卡。

## 导入微信开发者工具

1. 在微信开发者工具选择“导入项目”。
2. 项目目录选择本文件夹。
3. `project.config.json` 默认使用 `touristappid`，如课程要求使用自己的 AppID，在开发者工具中替换即可。
4. 编译后先依次测试首页、四关移动、撤回、重开、通关和标准作案路线。
5. 真机测试时重点检查 Canvas 图片是否加载、滑动手势和不同屏宽下的棋盘尺寸。

## 实现说明

为了避免课堂实验项目过度复杂，本版本没有加入排行榜、账号、云开发、商城、成就、皮肤等功能。核心差异化集中在视觉 IP、交互体验、统计、撤回、本地最佳成绩和最优解展示。

## 2026-09-01 UI / Canvas 修订

本版本针对开发者工具实测反馈做了以下调整：

- 修复 2D Canvas 本地图片路径被错误解析为 `pages/game/assets/...` 导致角色、罐罐、猫碗和纸箱图片无法显示的问题。
- 取消 Canvas 素材加载阶段的 `wx.getImageInfo`，改为由当前 Canvas 节点通过页面相对路径直接创建 Image 对象。
- 进入游戏页时延迟挂载 Canvas，降低页面切换阶段原生 Canvas 抢层导致上一页内容与棋盘短暂叠加的情况。
- 全站由深黑主题调整为暖米白 + 鼠尾草绿 + 深墨色，更突出黑猫主体，减少压抑感。
- 重做方向控制器：不再使用微信原生 button 作为方向键，改为完全可控的自定义猫爪 D-pad。
- 首页、游戏页、标准作案路线页同步统一为新的浅色视觉系统。

## V3 修复说明

- 修复 2D Canvas 在 `navigateTo / redirectTo` 页面转场期间压住上一页的问题：进入游戏页等待转场结束后才创建 Canvas；离开游戏页前先销毁 Canvas。
- 修复通关时 Canvas 原生层级压住结算弹层的问题：最终一步显示后先销毁 Canvas，再显示结算卡。
- 墙体格不再铺整块牛皮纸色背景；所有地图格统一使用奶油棋盘底色，纸箱图片叠加在格子上。
- 标准作案路线页将 `+ / −` 展开按钮改为“查看 / 收起”胶囊按钮。


## V4 Canvas 首帧定位修复

开发者工具中动态挂载 2D Canvas 时，原生层首次可能缓存错误屏幕坐标，表现为地图短暂上移覆盖统计栏，而轻微滚动页面后自动恢复。V4 在 Canvas 不可见阶段完成首帧绘制，并程序化执行 1px 页面位移后还原，强制刷新原生层坐标，随后再显示画布；同时 Canvas 明确绝对定位在棋盘容器内部。
