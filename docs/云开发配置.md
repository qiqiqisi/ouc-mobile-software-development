# 海大圈互动功能：云开发配置清单

本次已完成本地代码修改，**没有替你创建云集合、部署云函数或更改线上数据**。请按以下顺序配置。

## 1. 确认环境

打开微信开发者工具中的本项目 `D:\wechat_web\lab06`，点击「云开发」。当前代码使用的环境为：

```text
YOUR_CLOUD_ENV_ID
```

它对应 `config/cloud.js` 中的 `ENV_ID`。控制台右上角应选择同一个环境。

## 2. 新建四个空集合

进入「数据库 / 文档型数据库 → 集合管理 → 新建集合」。以下名称必须逐字一致，使用英文小写和下划线。

| 新集合名称 | 存储内容 | 是否需要手工添加记录 |
| --- | --- | --- |
| `post_reactions` | 点赞和收藏，一条记录表示一个用户对一篇笔记的一种互动 | 不需要 |
| `follows` | 用户之间的关注关系 | 不需要 |
| `comments` | 评论、回复目标、作者快照 | 不需要 |
| `browse_history` | 每个用户看过的笔记及最近访问时间 | 不需要 |

保留原来的 `users`、`posts` 集合与其中的数据。最终总共六个集合。

**不要手工填写 OpenID、虚构点赞数或插入示例记录。** 用户在小程序内操作后，云函数会自动生成记录及唯一文档 ID。

## 3. 设置数据库权限

六个集合全部通过云函数读写。逐个进入集合的「权限设置 / 权限管理」，选择「仅管理端可读写」或等价选项。

若控制台使用「自定义安全规则」，设置为：

```json
{
  "read": false,
  "write": false
}
```

这限制的是客户端直接操作数据库；小程序通过 `wx.cloud.callFunction` 调用云函数，由服务端使用微信上下文识别当前用户。浏览历史、收藏列表和点赞列表的查询都固定使用调用者身份，不接受客户端伪造的用户身份。

权限配置入口与规则语法可对照 [CloudBase 官方安全规则说明](https://docs.cloudbase.net/database/security-rules)。本项目代码决定了这里应采用管理端读写权限。

云存储沿用原来帖子图片和头像的配置，本次不新增云存储目录之外的服务。

## 4. 添加索引

逐个进入集合的「索引管理 → 添加索引」。下面均为**普通、非唯一索引**；字段顺序应与表中一致。

`升序` = ASC / 1，`降序` = DESC / -1。文档自带的 `_id` 唯一索引保留，不要删除。

| 集合 | 建议索引名 | 依次添加字段与排序 |
| --- | --- | --- |
| `posts` | `feed_time` | `createdAt` 降序，`_id` 降序 |
| `posts` | `feed_category` | `category` 升序，`createdAt` 降序，`_id` 降序 |
| `posts` | `author_posts` | `authorOpenid` 升序，`createdAt` 降序，`_id` 降序 |
| `posts` | `author_status` | `authorOpenid` 升序，`status` 升序，`createdAt` 降序，`_id` 降序 |
| `post_reactions` | `viewer_post` | `openid` 升序，`postId` 升序 |
| `post_reactions` | `viewer_library` | `openid` 升序，`type` 升序，`createdAt` 降序，`_id` 降序 |
| `follows` | `following_time` | `openid` 升序，`createdAt` 降序，`_id` 降序 |
| `follows` | `followers_time` | `targetOpenid` 升序，`createdAt` 降序，`_id` 降序 |
| `follows` | `follow_pair` | `openid` 升序，`targetOpenid` 升序 |
| `comments` | `post_comments` | `postId` 升序，`createdAt` 降序，`_id` 降序 |
| `comments` | `comment_author` | `openid` 升序 |
| `browse_history` | `viewer_recent` | `openid` 升序，`viewedAt` 降序，`_id` 降序 |

若已有相同字段与排序的索引，直接复用，不要重复添加。索引创建后等待状态变为可用。

索引名可以自定义；真正影响查询的是集合、字段顺序和升降序。这里的索引表来自本次代码实际使用的查询。

## 5. 部署两个云函数

回到开发者工具文件树，依次操作：

1. 右键 `cloudfunctions/login` → **上传并部署：云端安装依赖**。
2. 右键 `cloudfunctions/campusApi` → **上传并部署：云端安装依赖**。
3. 确认 `campusApi` 的整个文件夹已上传，包含新增的 **`social.js`**；不能只上传 `index.js`。
4. 等待部署成功，确认环境与第 1 步一致。
5. 建议将 `campusApi` 超时时间设为 60 秒，以容纳冷启动和批量清空浏览记录。清空已拆成每次最多 20 条，客户端会继续请求剩余批次。
6. 在开发者工具点击「编译」，重新进入小程序。首次加载等待微信身份初始化完成。

`login` 本次修复了首次并发创建用户可能覆盖已有资料的问题，因此也需要部署。

## 6. 旧数据需要添加字段吗？

**不需要逐条修改旧数据，不需要清空 `users` 或 `posts`。**

新增字段由云函数在后续操作中维护；缺失时页面按 0 处理：

| 集合 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| `posts` | `likeCount` | number | 收到的点赞数 |
| `posts` | `favoriteCount` | number | 被收藏的次数 |
| `posts` | `commentCount` | number | 当前评论数，回复也计入 |
| `users` | `followingCount` | number | 关注人数 |
| `users` | `followerCount` | number | 粉丝人数 |
| `users` | `receivedLikes` | number | 当前公开笔记收到的点赞 |
| `users` | `receivedFavorites` | number | 当前公开笔记被收藏的次数 |

新互动记录使用服务端生成的毫秒时间戳。原有帖子的 `createdAt` / `updatedAt` 保持原来日期格式，前端日期工具兼容两者。

如果你自行修改计数或手工添加互动关系，计数与关系可能不再一致；日常使用请通过小程序操作。

## 7. 配置完成后验收

使用你控制的两个测试账号与测试笔记，按以下流程确认实际云环境：

1. 账号 A 打开账号 B 的笔记：点赞、取消点赞、收藏、取消收藏，确认计数和蓝色选中态同步。
2. A 关注 B，进入「我的 → 关注」能找到 B；B 进入「我的 → 粉丝」能找到 A；再次取消关注验证两边计数。
3. A 发送评论，回复 B 的评论；A 可删除自己的评论，不能删除 B 的评论。
4. 关闭并重新打开小程序，确认点赞、收藏、关注和评论仍在。
5. 「我的 → 收藏 / 点赞」能打开对应笔记；取消后返回对应列表，记录应消失。
6. 「我的 → 浏览记录」按最近访问时间排序；重复打开同一笔记只保留一条。切换账号后不应看到对方的历史。
7. 在历史页「管理」中移除单条或清空全部，确认不会清空收藏或影响他人。
8. 分别检查首页、详情、我的、TA 的主页、发布、编辑资料、历史、关注与粉丝共 8 个页面。
9. 用真机检查评论键盘弹出/收起、长图与多图预览、底部安全区、快速滑动、相册保存和微信分享。

这些操作由你自行决定是否执行，本次没有向云端插入或删除测试数据。

## 常见问题

| 表现 | 首先检查 |
| --- | --- |
| 点赞或评论提示「未知操作」 | 仍在使用旧 `campusApi`，重新部署整个文件夹 |
| 日志提示集合不存在 | 四个新集合名称是否正确，是否建在当前环境 |
| 提示缺少索引或列表加载失败 | 按第 4 步补齐索引，等待创建完成后重试 |
| 修改代码后仍是旧界面 / 提示新页面文件不存在 | 先点击编译；必要时清除编译缓存后重新编译，不要清空云数据库 |
| `Cannot find module './social'` | 部署漏了 `cloudfunctions/campusApi/social.js` |
| 用户身份初始化失败 | `login` 是否部署到同一环境，`users` 集合是否存在 |

本次本地验证结果见同目录的 `测试与验收.md`。
